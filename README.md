# REST API для Дошки Оголошень

Це повноцінний RESTful API для сервісу "Дошка оголошень", розроблений на базі Node.js, Express 5 та Prisma ORM (SQLite). Сервер спілкується з клієнтом виключно за допомогою JSON-даних.

## Функціонал

- **Отримання списку оголошень** (`GET /announcements`) — підтримує пошук по назві (`search`), сортування за датою (`sort=newest|oldest`) та пагінацію (10 записів на сторінку). Запити бази даних виконуються паралельно через `Promise.all` для оптимізації продуктивності.
- **Отримання оголошення за ID** (`GET /announcements/:id`) — повертає дані одного оголошення або `404`, якщо його не знайдено.
- **Створення оголошення** (`POST /announcements`) — створює нове оголошення після проходження серверної валідації через `celebrate`.
- **Часткове оновлення оголошення** (`PATCH /announcements/:id`) — дозволяє змінювати будь-яку підмножину полів (потрібно передати хоча б одне поле). Поле `updatedAt` оновлюється автоматично.
- **Видалення оголошення** (`DELETE /announcements/:id`) — видаляє запис та повертає HTTP-статус `204 No Content` без тіла відповіді.

## Технологічний стек

- **Backend**: Express 5 (автоматична обробка помилок в асинхронних функціях)
- **Database ORM**: Prisma Client v7 (адаптер SQLite через `better-sqlite3`)
- **Validation**: Celebrate / Joi
- **Documentation**: Swagger UI & Swagger JSDoc (OpenAPI 3.0.0)

## Швидкий старт

1. **Встановлення залежностей**:
   ```bash
   npm install
   ```

2. **Налаштування файлу середовища (`.env`)**:
   Створіть файл `.env` у корені проєкту:
   ```env
   DATABASE_URL="file:./dev.db"
   ```

3. **Створення міграції та ініціалізація бази даних**:
   ```bash
   npm run prisma:migrate
   ```

4. **Запуск сервера**:
   ```bash
   npm run dev
   ```
   Сервер запуститься на порту 3000.

## Документація API (Swagger UI)

Інтерактивна документація Swagger доступна у браузері після запуску сервера за адресою:
👉 **[http://localhost:3000/api-docs](http://localhost:3000/api-docs)**

Тут можна детально ознайомитися зі схемами запитів/відповідей та протестувати будь-який маршрут у реальному часі.

## Тестування за допомогою REST Client

У корені проєкту знаходиться файл `requests.http`, який містить 11 готових прикладів запитів для тестування всіх маршрутів безпосередньо з VS Code за допомогою розширення **REST Client**:
- GET /announcements (без параметрів, з пошуком, з сортуванням та пагінацією)
- GET /announcements/:id (успішний та неуспішний варіанти)
- POST /announcements (з валідними та невалідними даними)
- PATCH /announcements/:id (часткове оновлення існуючого та спроба оновлення неіснуючого)
- DELETE /announcements/:id (видалення існуючого та спроба видалення неіснуючого)

## Структура коду

Код організовано за трирівневою архітектурою:
- **`src/routes/`** — описує кінцеві точки API, підключає валідатори та контролери, а також містить JSDoc-коментарі для Swagger.
- **`src/controllers/`** — містить логіку обробки запитів та звернень до бази даних через Prisma Client.
- **`src/validators/`** — описує Joi-схеми для валідації query, params та body за допомогою бібліотеки `celebrate`.
